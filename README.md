# Kung Fu Codes

Static site for the Código(s) Kung Fu brand: one Hugo codebase building three independent sites, one per language.

| Language | Domain |
|---|---|
| Portuguese | [codigoskungfu.com](https://codigoskungfu.com) |
| English | [kungfu.codes](https://kungfu.codes) |
| Spanish | [codigoskungfu.eu](https://codigoskungfu.eu) |

## Project history

kungfu.codes started in 2022 as a personal blog about Kung Fu and systems thinking. The domain lapsed and got re-registered in 2026 for a career pivot: Código(s) Kung Fu, aimed at Portuguese and Spanish speaking developers. The old Portuguese articles stayed on the PT site. English is now the brand's main track, and Spanish covers the second market.

## Architecture

### Multihost, not subpaths

Each language sets its own `baseURL` and `contentDir` in `config/_default/languages.*.toml`, which turns on Hugo's multihost mode. One `hugo` build produces three output trees:

```
public/pt/   → codigoskungfu.com
public/en/   → kungfu.codes
public/es/   → codigoskungfu.eu
```

Each tree carries absolute URLs for its own domain. No `/en/` prefix, no client-side language detection.

### Content isn't mirrored

`content/pt/`, `content/en/` and `content/es/` are independent trees, and a page only needs to exist where it's actually written. Hugo links a page to its translations when a matching path shows up in another language directory, and builds the `hreflang` tags from whatever translations it finds. Most untranslated pages carry no placeholder at all; one does right now, noted below.

### Layout: Silva's look, no theme

The site has no Hugo theme. `layouts/` reproduces the visual of [Silva](https://silva.thluiz.com) (an Astro site built on the Astro Cactus theme, repo `E:/silva`): mono font, narrow column, seal in the header, card mosaic on home/lists/tags, posts inside a box with an optional TOC, tag cloud, Ctrl+K search dialog. Tailwind isn't used; `assets/css/main.css` is a hand port of the utility classes Silva uses plus its `post-card.css`, and `assets/js/main.js` replaces its web components (theme toggle, mobile menu, search, back-to-top). UI strings live in `i18n/{pt,en,es}.yaml`. `layouts/shortcodes/` (`sifu`, `instituto`, `ipanema`, `mdbg`, `sitaigung`) are small link shortcodes.

### Decision: own layouts instead of adapting Blowfish (2026-10-03)

Blowfish was the theme until the Silva look was requested. Matching it meant overriding header, cards, single, home and lists anyway, on top of Blowfish's precompiled Tailwind CSS (which has none of the classes those layouts need), so the layouts were rewritten and the theme dropped.

The cost is real and accepted: **anything Blowfish already ships and maintains has to be ported by hand, and kept up to date by hand.** That is why the submodule stays at `themes/blowfish`, unused by the config, as the source for ports and for diffing when Blowfish releases a new version. Don't remove it.

Ported so far (from Blowfish v3.8.0-2-ga0624527):

| Component | Files here | Notes |
|---|---|---|
| `alert` | `layouts/shortcodes/alert.html`, icons in `assets/icons/alert/` | Same params (`icon`, `cardColor`, `iconColor`, `textColor`) |
| `mermaid` | `layouts/shortcodes/mermaid.html`, `assets/lib/mermaid/` (11.x, MIT) | Palette colors, re-renders on theme toggle |
| `chart` | `layouts/shortcodes/chart.html`, `assets/lib/chart/` (Chart.js 4.5.1, MIT) | Palette colors, updates on theme toggle |
| `gallery` | `layouts/shortcodes/gallery.html` + `.gallery` rules in `main.css` | Same `grid-wNN` / `md:grid-wNN` classes, laid out with flex-wrap. Blowfish's Packery dependency (GPLv3) was left out, so no masonry packing |

Libraries load only on pages that use the shortcode (`layouts/partials/vendor.html`). Porting another component: copy the shortcode from `themes/blowfish/layouts/shortcodes/`, rewrite its Tailwind classes as plain CSS in `main.css` using the palette variables, copy any `assets/lib/` dependency (check its license), wire it in `vendor.html`, and add a row above.

Code blocks use Hugo's Chroma with CSS classes (`markup.highlight.noClasses = false`): github style in light mode, dracula in dark, as on Silva. `assets/css/syntax.css` is generated by `hugo gen chromastyles`, scoped by `data-theme`; regenerate it instead of editing. `main.js` adds a copy button to each block.

### Colors: mcys

Silva's structure, with the Moy Chi Yau Si family palette instead of Silva's green: purple accent on Ghost White in light mode, gold on Russian Violet in dark mode. All colors are the CSS variables at the top of `main.css`. Moy Chi Yau Si is a family within the Moy Jo Lei Ou clan.

### Posts that come from Silva

Most articles are republished from Silva, which is their source: 8 in `pt/kungfu`, 5 in `pt/codigos`, 2 in `en/codes`. Each one carries `canonicalURL` (pointing at `silva.thluiz.com/posts/<slug>/`), `silvaeSlug` and `silvaeCommit` (the last Silva commit that touched that post when it was imported). Slugs match Silva's.

```sh
python scripts/silvae.py check                      # which posts changed in Silva since import (exit 1 if any)
python scripts/silvae.py pull --outdated            # re-import those, each where it already lives
python scripts/silvae.py pull <slug>                # (re)import into pt/kungfu
python scripts/silvae.py pull --to en/codes <slug>  # any <lang>/<section> under content/
```

What stays only on Silva: heavy philosophy and politics (`organizacoes-contra-a-entropia`, `welcome`), linguistics (`academia-sinica-2000-anos-etimologia`), the Programa de Mestrado records, and the travel diaries (SIVKF, Buenos Aires) as they are.

### Tags across languages

Each post uses tags in its own language, so URLs stay native (`/tags/carreira/` on the PT site, `/tags/career/` on the EN one). `data/tags.toml` is the dictionary: one table per concept, with its name in `pt`, `en` and `es`. `scripts/tags.py sync` generates `content/<lang>/tags/<slug>/_index.md` for every tag used by a published post, with `translationKey: "tag-<key>"`. That key is what links the same tag across the three sites in the language switcher and hreflang.

- Same spelling in two languages (`sistemas` in PT and ES, `kung fu` everywhere): same key, so the pages are linked.
- False cognate (same spelling, different meaning): separate keys. Example of the opposite trap: PT `historietas` maps to ES `anécdotas`, because in Spanish "historieta" means comic strip.
- `pt` names are exactly what Silva uses. `scripts/silvae.py` translates tags through the dictionary when importing into `en/` or `es/`, since Silva writes PT tags even on English posts.

```sh
python scripts/tags.py check  # unknown tags or stale tag pages (exit 1); deploy.ps1 runs it and warns
python scripts/tags.py sync   # (re)generate tag pages after adding tags or editing the dictionary
python scripts/tags.py fix    # rewrite post tags to the dictionary name in the post's language
```

A new tag needs a dictionary entry before `sync`; until then `check` flags it and its page has no translations.

### Sections

`kungfu` (all three sites) and Códigos/Codes for development, architecture and career: `content/pt/codigos/` and `content/en/codes/`, linked as translations through `translationKey: "codigos"`. `mainSections` lists all three section names; Spanish gets the section once it has content.

`deploy.ps1` runs the check on every deploy and warns, without blocking. The script reads `E:/silva` from disk and warns when that clone is behind `origin`.

## Deployment

Each `public/<lang>` folder ships to its own S3 bucket and CloudFront distribution, set up the same way as Scholion. AWS account 137566891486, region `us-east-1`, profile `scholion-admin`.

| Language | Domain | Bucket | CloudFront ID | CloudFront domain |
|---|---|---|---|---|
| PT | codigoskungfu.com | `codigoskungfu-com` | `EK2VP6A6SJGYU` | `d2gs748mexp442.cloudfront.net` |
| EN | kungfu.codes | `kungfu-codes` | `E338DCHVHBSHR6` | `d1xbwrtnltobcs.cloudfront.net` |
| ES | codigoskungfu.eu | `codigoskungfu-eu` | `E3OF7PAIONYLFN` | `d3c5ut3f24wsc.cloudfront.net` |

- Private buckets, read through a shared OAC (`kfcodes-oac`).
- ACM certificate per domain covering apex + `www`; both are aliases on the distribution.
- CloudFront function `kfcodes-rewrite-uri` (viewer-request): 301 from `www.` to the apex, then rewrites `/path/` to `/path/index.html` (copied from Scholion's `scholion-rewrite-uri`).
- 403/404 served as `/404.html`.
- DNS in Cloudflare: apex and `www` CNAME to the CloudFront domain, plus the ACM validation CNAMEs (keep them, renewal depends on them).

```powershell
pwsh -NoProfile -File deploy.ps1              # build + publish all three
pwsh -NoProfile -File deploy.ps1 -Lang en     # one site only
pwsh -NoProfile -File deploy.ps1 -SkipBuild   # publish the current public/
pwsh -NoProfile -File deploy.ps1 -ForceFullSync
```

`deploy.ps1` hashes every file under `public/<lang>`, uploads only what differs from the local manifest (`.deploy/manifest-<lang>.json`, gitignored), deletes what disappeared, and invalidates the distribution only when something changed. It uses `aws s3 cp`, never `s3 sync`, because Hugo rewrites every mtime on each build.

### Language switcher

`layouts/partials/header.html` lists the three sites with absolute URLs (each language is another domain). When the page has no translation, the link goes to the other site's home.

### Search

[Pagefind](https://pagefind.app), as on Silva. `deploy.ps1` runs `npx pagefind --site public/<lang>` after the Hugo build, so each site gets its own index at `/pagefind/`. Only posts are indexed (`data-pagefind-body`). Search only works on the built output, not under `hugo server`.
